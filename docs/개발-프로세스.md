# 개발 프로세스 (요청, 빌드, 테스트, 배포)

> **모든 세션이 반드시 따라야 하는 프로세스의 단일 기준(SSOT)입니다.**
> 빌드, 산출물 규칙, 검증 방법은 AI 메모리가 아니라 이 문서를 근거로 처리합니다.
> 이 틀을 가져다 쓰는 프로젝트는 배포 절을 제 것으로 고쳐 씁니다.

---

## 0. 매 요청 공통 원칙

- **언어**: 한국어. 코딩 스타일은 `CLAUDE.md`.
- **가상의 API 금지**: 코드베이스에 실제 있는 함수, 클래스만.
- **임시 파일**: 리포 안에 만들지 않습니다. 세션 스크래치패드를 씁니다.
- **문서 스탬프**: 모든 `docs/*.md` 맨 위에 `> _작업 PC: <hostname>, 최종 수정: YYYY-MM-DD HH:MM_`.

## 1. 프로젝트 형태

- 가로 전용 1280 × 800(스팀덱), 웹으로 테스트, 스팀은 Electron 으로 묶습니다.
- **엔진**: `libs/vanilla.js`, 원본 리포(https://github.com/ddukbaek2/vanilla.js)의 **파일 복사본**.
  2026-09-07 에 `D:\Github\The Unreliable Twelve` 의 것을 통째로 복사했습니다. (그쪽 보완분 포함, `docs/엔진-보완-내역.md`)
  2D 렌더러는 WebGL2 입니다. 글자는 오프스크린 캔버스에 구워 텍스처로 그립니다.
- 빌드 도구는 엔진의 `libs/vanilla.js/tools/project.cjs` + `tools/cachebust.cjs`.
- 퍼즐 규칙(`src/logic/`)은 브라우저와 Node 양쪽에서 돕니다. `src/logic/package.json` 이 그 폴더를 ESM 으로 선언합니다. (프로젝트는 commonjs 라 Node 가 `.js` 를 CJS 로 보기 때문입니다)

## 2. 실행 / 빌드

- **개발 실행**: 정적 서버로 프로젝트 루트를 서빙하고 `launcher.html`.
  ```powershell
  python -m http.server 8000
  # http://localhost:8000/launcher.html
  ```
- **의존성**: 최초 1회 `npm install`. (esbuild) 데스크탑 판은 `npm install --prefix platforms/desktop`. (electron, electron-builder)
- **웹 빌드**: `npm run build` → `build/web`. `assets/` 가 통째로 복사됩니다. (글꼴 2 MB 남짓)
- **새 게임 추가**: `docs/게임-모듈-규약.md`. (`src/games/<id>/` + `src/game/games.js` 등록 + `docs/games/<id>.md` + `qa/run-<id>.cjs`)
- **여러 편을 병렬로 만들 때**: 게임마다 git worktree(`.claude/worktrees/`)에서 서버 포트를 달리해(8841 ~) 만들고, 스크래치패드 `merge-game.sh <id> <worktree>` 로 옮긴 뒤 `register-games.py <id …>` 로 `games.js` 를 다시 씁니다. worktree 는 `git worktree remove --force` 로 지웁니다.
- **데스크탑(스팀) 판**:
  ```powershell
  npm run build              # 웹 산출물
  npm run stage:desktop      # build/web 을 platforms/desktop/web 으로 옮김
  npm run start:desktop      # Electron 으로 바로 띄워 봄 (F11, Alt+Enter 전체 화면)
  npm run build:desktop      # 실행 파일 build/desktop/win-unpacked
  npm run build:steam -- --appid <앱 번호>   # steam_appid.txt, vdf 채움 → steamcmd 명령 안내
  ```
  스팀 앱 번호는 `.env` 의 `STEAM_APP_ID` 에 둡니다. (아직 비어 있습니다)
- **파비콘**: `python tools/generate-favicon.py [.assets-raw/Galmuri11.ttf]`. (갈무리 배포판의 TTF, `.assets-raw/` 는 리포에 넣지 않습니다)

## 3. 작업 마무리 워크플로

순서: **① git 커밋 → ② 웹 빌드 → ③ 헤드리스 검증 → ④ 배포 → ⑤ 작업 로그**

1. **git** 커밋. (`node_modules` / `build` / `.logs` / `.assets-raw` / `platforms/desktop/web` 는 gitignore)
   엔진(`libs/vanilla.js`)을 고쳤으면 **원본 리포에 먼저 올리고** 서브모듈을 그 커밋으로 옮깁니다.
2. **웹 빌드**, `npm run build`. 서빙 중인 서버가 있으면 먼저 내립니다. 빌드는 `build/web` 을
   통째로 지우고 다시 만듭니다. 그 안에 손으로 넣은 것은 매번 사라지므로, 함께 실을 것이 있으면
   빌드 스크립트 끝에 붙입니다.
3. **헤드리스 검증**, §4.
4. **배포.** 이 틀에는 정해진 배포처가 없습니다. 가져다 쓰는 프로젝트가 여기에 제 절차를 적습니다.
5. **작업 로그**, `.logs/claude-YYYY-MM-DD.log` 에 `[HH:MM 요청 → HH:MM 응답] 내용`. 날짜당 1 파일.

## 4. 테스트 / 검증 (헤드리스 크롬)

- 스크립트는 스크래치패드에 둡니다. (리포에 넣지 않습니다) 틀은 이렇습니다.
  - 정적 서버 **포트 8819** (8123, 8791, 8817 은 다른 프로젝트가 씁니다), `puppeteer-core` 는 `D:/Github/game-qa-simulator/node_modules` 것을 절대 경로로 require.
  - 크롬 `C:/Program Files/Google/Chrome/Application/chrome.exe`, 창 1280 × 800,
    `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` (WebGL2).
  - `pageerror` / `console.error` / `requestfailed` 를 모읍니다. `[GamepadManager]` 로그는 게임패드가 꽂혀 있어 나는 것이라 걸러 냅니다.
  - `main.js` 가 엔진을 `window.engine` 에 두므로 `engine.getSceneManager().getAllLoadedScenes()[0].getRoot()` 로 노드를 읽습니다. 켜진 화면은 루트 자식 중 `isActive()` 인 것입니다. 플레이 화면은 `findChildByName("playScreen").getView()` 로 상태, 수, 풀림을 읽습니다.
- **공용 도우미 `qa/harness.cjs`**(스크래치패드): `launch` → `enterGame(page, "<id>")`(타이틀 → 허브(여러 열 목록, 열 수는 허브에서 읽습니다) → 게임) → `press`, `readScreenKey`, `readModuleValue`, `shot` → `finish`. 게임마다 `qa/run-<id>.cjs` 가 이것을 씁니다(`docs/게임-모듈-규약.md` §4).
  장마다 1, 15, 30 번 판을 풉니다. 스크린샷을 눈으로 확인합니다. (글자 겹침, 잘림, 커서 표식)
- **다른 게임의 밟는 길**: 각 `docs/games/<id>.md` 의 "검증" 절. 들어가기 → 새로 시작 → 핵심 흐름 30 ~ 100 수 → 저장 → 게임 목록으로 → 이어하기 → 오류 0.
- 장별 입력 변환기(스크립트의 `MOVE_DRIVERS`)는 `docs/게임-기획.md` §3 의 조작을 그대로 옮긴 것입니다. 조작이 바뀌면 변환기도 바꿉니다.
- 게임의 입력은 `keydown` 의 `code` 로 받습니다. 헤드리스에서는 `page.keyboard.press("ArrowLeft")` 처럼 넣고, 연출이 있는 수 뒤에는 0.3 초쯤 기다립니다.
- 스크립트는 환경 변수로 돌립니다: `QA_PORT`(기본 8819), `QA_ROOT`(프로젝트 루트), `QA_SHOTS`(스크린샷 폴더), `QA_PAGE`(기본 `launcher.html`, 빌드 산출물은 `build/web` 을 8820 에 띄우고 `index.html`).
  인자: `node run.cjs [장 id] [판 번호,번호]` (없으면 전 장의 1, 6, 12 번). 전 장 검증은 12 분쯤 걸립니다.
- 여러 장을 병렬로 만들 때는 git worktree(`.claude/worktrees/`)에서 장별로 서버 포트를 달리해(8821 ~ 8826) 검증하고, 합친 뒤 `git worktree remove --force` 로 지웁니다.
